# PEPA Events — Mandatory Acceptance Checklist

Use this to prevent omissions. For whole-module work, every item must be checked explicitly.

## A. Shared architecture
- [ ] One common event engine; no duplicated mini-app architectures.
- [ ] Birthday, Communion, Baptism, Anniversary/Celebration, Intimate Wedding, Custom Event supported/configurable.
- [ ] Modules can be hidden and reactivated.
- [ ] User can choose modules during event setup.
- [ ] Venue-included services can influence recommended modules.

## B. Dates
- [ ] Pending date supported.
- [ ] Provisional date supported.
- [ ] Confirmed date supported.
- [ ] Relative tasks recalculate when date changes.
- [ ] Firm Calendar writes are not made from an unconfirmed date without user approval.

## C. Event home
- [ ] Shows useful headline summary.
- [ ] Shows actual pending items, not only count.
- [ ] Avoids a wall of too many blocks.
- [ ] PEPA conclusions/recommendations are contextual.

## D. Guests
- [ ] Minimal entry: name/family + adults + children.
- [ ] No required contact import.
- [ ] Guest total auto-calculated.
- [ ] Confirmed adult/child totals auto-calculated.
- [ ] Group/family entries supported.

## E. Invitations editor
- [ ] Template/theme first.
- [ ] Event data auto-filled and editable.
- [ ] Layered mobile editor.
- [ ] Text layer.
- [ ] Emoji/sticker layer.
- [ ] Decorative image layer.
- [ ] User photo/image layer.
- [ ] Background layer.
- [ ] Drag.
- [ ] Pinch resize.
- [ ] Rotate.
- [ ] Colour/size/font actions.
- [ ] Duplicate/delete.
- [ ] Bring forward/send backward.
- [ ] Undo.
- [ ] Restore template.
- [ ] Advanced controls secondary.
- [ ] Optional `Pepa, hazla bonita` action.
- [ ] No unlicensed built-in copyrighted character packs.

## F. Sharing + RSVP
- [ ] Native device share sheet.
- [ ] No PEPA app/account required for invitee.
- [ ] Personalized tokenized RSVP links.
- [ ] Open-link mode optional.
- [ ] Pending / confirmed / not attending / unsure.
- [ ] Adult + child counts.
- [ ] Recipient can edit response later.
- [ ] RSVP updates event automatically.
- [ ] Wrong-link handling.
- [ ] Link regeneration/invalidation.
- [ ] RSVP deadline.
- [ ] Manual reminder-to-pending workflow.
- [ ] Subtle PEPA branding + smart store/download link when available.

## G. Budget / data reuse
- [ ] Do not duplicate Economy transactions.
- [ ] Tag/label event spending initially where needed.
- [ ] Menu before shopping.
- [ ] User confirms transfer to Purchases.
- [ ] User confirms important Calendar writes.

## H. Birthday
- [ ] Age turning required.
- [ ] Date optional initially.
- [ ] Indoor play centre/ball park venue supported.
- [ ] No approximate guest count field at creation.
- [ ] Adult AND child/teen invitation styles.
- [ ] Decoration optional.
- [ ] Activities contextual.
- [ ] No shared birthday photo album/page.

## I. Communion
- [ ] Two locations supported.
- [ ] Guest scope: both / ceremony only / celebration only.
- [ ] Invitation includes only selected relevant location(s).
- [ ] Ceremony module.
- [ ] Tables module.
- [ ] Restaurant/menu.
- [ ] Details/keepsakes.
- [ ] Payments/deposits.
- [ ] Providers.
- [ ] Private gifts/money received.
- [ ] Net event cost summary.

## J. Baptism
- [ ] Communion-like but lighter defaults.
- [ ] Godparents supported.
- [ ] Two-location invitation scope.
- [ ] Optional tables/details/photo/clothing/gifts.

## K. Anniversary / celebration
- [ ] Multiple celebration subtypes.
- [ ] Surprise mode + anti-spoiler warning behavior.
- [ ] Adult invitation styles.
- [ ] Optional activities.

## L. Intimate wedding
- [ ] Based on Communion structure.
- [ ] Couple names.
- [ ] Ceremony type.
- [ ] Optional witnesses.
- [ ] Clothing/rings/flowers/music/photo/transport/cake options.
- [ ] Tables.
- [ ] Invitation scope by ceremony/celebration.
- [ ] NO external/store gift registry.
- [ ] Private gifts received remains available.
- [ ] Special details for parents/witnesses/godparents/etc.

## M. Custom event
- [ ] Minimal creation.
- [ ] Any relevant module selectable.
- [ ] PEPA module recommendations optional.
- [ ] Personal reusable template supported.

## N. End of event
- [ ] Event-day focused view.
- [ ] Finish/archive without data loss.
- [ ] End summary.
- [ ] Duplicate/reuse without copying old RSVP/expenses as live state.

## O. AI behavior
- [ ] AI proposes; user confirms important writes.
- [ ] `Organízamelo PEPA` implemented in staged/reliable fashion.
- [ ] Conclusions actionable and linked to relevant section where possible.
